# JobHunter Git 与发布规范

> 对应开发清单 `P0-08`。本文作为比赛版开发与演示部署的最小规范。

## 一、分支规范

| 分支 | 用途 |
|---|---|
| `main` | 唯一稳定主线，演示环境只从该分支更新 |
| `feat/*` | 功能开发分支，例如 `feat/p0-layout` |
| `hotfix/*` | 演示前紧急修复分支 |

## 二、提交规范

建议提交信息使用：

```text
[类型] 简短说明
```

示例：

```text
[init] 初始化前后端工程骨架
[feat] 完成首页驾驶舱基础布局
[fix] 修复 persona 切换状态错乱
```

## 三、发布规范

1. 本地开发完成后提交到 Git；
2. 合并到 `main` 前运行 `make health`；
3. 演示环境通过 `make upgrade` 从 `origin/main` 快进更新；
4. 比赛前稳定版本打 tag，例如 `demo-v0.1.0`；
5. 演示现场不直接编辑服务器代码。

## 四、回滚原则

- 回滚只回到最近一个稳定 tag；
- 回滚前保留 `logs/ops/` 中的升级与迁移日志；
- 迁移失败时优先恢复备份数据，不直接手工改库。
