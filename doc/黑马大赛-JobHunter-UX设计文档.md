# JobHunter 黑马大赛 UX 设计文档

> **项目方向**：AI 求职作战中枢  
> **文档版本**：v1.4  
> **更新日期**：2026-06-03  
> **设计目标**：前端先行、全平台适配、比赛演示稳定、交互可落地  
> **适配范围**：桌面 Web / 平板 / 手机 / 大屏演示 / PWA  
> **视觉基准**：以已确认的首页高保真图为 Base，后续前端开发优先还原该风格和信息层级。

---

## 一、UX 总目标

JobHunter 的 UX 不做传统“表单型求职工具”，而是做一个 **求职作战中枢**。

用户进入产品后，需要快速感知：

1. 我是谁：系统理解了我的职业素材和能力画像；
2. 我正在以什么身份求职：多求职身份明确当前方向；
3. 当前机会在哪里：热度广场告诉我全局和个人倾向；
4. 招聘官会怎么看我：招聘官视角指出亮点和疑点；
5. 哪些岗位值得投：岗位不是列表，而是决策卡；
6. 我现在该做什么：求职冲刺计划和管线告诉我下一步；
7. 哪个简历版本更有效：简历版本实验给出反馈；
8. AI 为什么这么建议：所有建议都有证据；
9. 我的求职过程是否在变好：反馈复盘形成闭环。

## 二、核心 UX 原则

### 2.1 决策优先

页面不只是展示信息，而是帮助用户做决策。

错误方向：

```text
展示 100 个岗位，用户自己挑。
```

正确方向：

```text
告诉用户：这 5 个岗位最值得投，为什么值得投，下一步该做什么。
```

### 2.2 探索优先

首次进入的用户可能没有明确求职方向。  
因此需要先给一个“机会热度广场”，帮助用户发现：

- 哪些岗位方向热；
- 哪些技能增长快；
- 哪些城市机会多；
- 哪些方向更适合当前用户。

### 2.3 身份优先

用户可能同时探索多个方向。  
界面需要始终显示当前求职身份，例如：

```text
当前身份：AI 应用工程师
```

切换身份后，热度广场、岗位雷达、决策卡、简历版本和管线都要跟着切换。

### 2.4 招聘官视角优先

用户不只关心“我觉得自己合适”，还关心“招聘官会不会筛我”。  
UX 需要提供 Recruiter Lens：

- 第一眼印象；
- 简历亮点；
- 简历疑点；
- 筛选风险；
- 可能追问；
- 提升建议。

### 2.5 行动节奏优先

首页不仅展示数据，还要给出今天该做什么。

```text
今日求职 Sprint：
1. 投递 2 个 P0 岗位
2. 跟进 3 天前投递的岗位
3. 补充 RAG 项目素材
```

### 2.6 证据优先

AI 生成内容必须有来源。

每条简历优化、面试建议、岗位推荐都尽量展示：

- 来源项目；
- 原始经历；
- 量化指标；
- 关联技能。

### 2.7 状态可见

用户必须知道系统正在做什么。

所有长耗时行为都需要状态：

- 正在加载；
- 正在生成；
- 已完成；
- 失败；
- 可重试；
- 使用 Mock 数据；
- 正在更新版本。

### 2.8 前端先行

当前阶段先保证页面和交互完整。

所有算法结果都可以先用 Mock 数据驱动。  
后续算法同学只需要按 Schema 替换数据，不影响 UX 结构。

### 2.9 全平台一致

桌面端强调信息密度，移动端强调行动闭环，大屏强调演示冲击力。

### 2.10 首页视觉基准优先

当前已确认首页高保真图作为 JobHunter 的主视觉基准。后续不再为每个页面单独追求完全不同的视觉稿，而是以首页沉淀统一设计系统：

- 左侧固定导航；
- 顶部用户区、求职身份切换和更新提示；
- 深蓝黑背景、细网格、弱粒子、玻璃拟态卡片；
- 青绿色 / 电光蓝作为主强调色；
- 首页 Hero + 雷达图；
- 指标卡、任务卡、岗位卡、热度卡、管线卡保持同一套圆角、边框、阴影和高亮规则。

页面层级约束：

- `岗位决策卡` 是 `岗位雷达` 的详情页，不作为左侧一级导航；
- `招聘官视角` 是岗位决策卡内嵌模块或详情抽屉，不作为左侧一级导航；
- `多求职身份` 主要通过顶部身份切换器进入管理，不作为左侧一级导航；
- `职业素材库` 保留为核心能力，但不强制出现在左侧一级导航，可从首页 Sprint、简历工作室、决策卡风险修复入口进入。

## 三、目标用户与使用场景

### 3.1 目标用户

| 用户类型 | 核心诉求 |
|---|---|
| 社招候选人 | 快速判断岗位是否值得投，减少无效投递 |
| 校招学生 | 不知道简历如何匹配岗位，需要方向感 |
| 转岗用户 | 需要识别技能缺口和成长路径 |
| 比赛评委 | 希望快速看到创新点、完整度和演示效果 |

### 3.2 核心使用场景

1. 用户登录；
2. 选择求职身份；
3. 查看今日求职 Sprint；
4. 查看机会热度广场；
5. 维护职业素材；
6. 扫描岗位；
7. 查看岗位决策卡；
8. 查看招聘官视角；
9. 加入求职管线；
10. 生成定制简历；
11. 查看简历版本实验；
12. 查看面试作战卡；
13. 记录投递反馈；
14. 复盘下一轮策略。

### 4.2 全局导航

桌面端左侧导航：

```text
Logo
├── 首页
├── 机会广场
├── 岗位雷达
├── 求职管线
├── 简历工作室
├── 面试作战卡
├── 反馈复盘
└── 设置
```

导航规则：

- 左侧导航以首页高保真图为准，保持 8 个主入口，避免比赛 Demo 导航过重；
- `职业素材库` 不从左侧主导航直达，默认作为 `简历工作室` 的 Tab / 子页面；
- 首页 Sprint 中的“补充 RAG 项目素材”可以直接跳转到职业素材库；
- 岗位决策卡中的风险修复建议可以直接跳转到职业素材库；
- `岗位决策卡`、`招聘官视角`、`简历版本实验` 使用面包屑、抽屉或页面内入口进入；
- 顶部求职身份切换器始终可见，承担“多求职身份”的主入口功能。

移动端底部导航：

```text
首页 / 广场 / 岗位 / 管线 / 我的
```

## 五、核心用户旅程

### 5.1 首次进入

```text
打开产品
  ↓
登录 / 注册 / 演示账号进入
  ↓
进入首页驾驶舱
  ↓
选择或确认当前求职身份
  ↓
查看今日求职 Sprint
  ↓
查看机会热度广场
  ↓
提示：先建立职业素材库
  ↓
加载 Demo 素材或上传简历
  ↓
生成求职画像
```

关键 UX：

- 首页必须有“演示账号进入”；
- 不要让评委卡在注册流程；
- 首次进入用引导卡片告诉用户下一步。
- 如果用户没有画像，热度广场展示全局热门；
- 如果已有画像，热度广场展示“更适合你”的方向。
- 当前求职身份必须在首页和全局导航中可见。

### 5.2 切换求职身份

```text
通过顶部求职身份切换器
  ↓
查看已有身份：后端开发 / AI 应用工程师 / 技术产品经理
  ↓
切换到 AI 应用工程师
  ↓
热度广场、岗位雷达、管线、简历版本同步切换
```

关键 UX：

- 切换身份后必须有清晰反馈；
- 不同身份的数据边界要清楚；
- 移动端可以在“我的”页面中切换身份；
- 桌面端可以在顶部全局栏显示身份切换器。

### 5.3 发现方向

```text
进入机会热度广场
  ↓
冷启动默认展示全局热度
  ↓
若有用户画像，默认展示我的倾向，并可切换全局热度对比
  ↓
点击某个热门方向
  ↓
带筛选条件进入岗位雷达
```

关键 UX：

- 第一次进入不能空白；
- 全局热度适合冷启动；
- 我的倾向适合登录后用户；
- 热度卡片必须能直接进入岗位雷达。

### 5.4 找岗位

```text
进入岗位雷达
  ↓
查看 Top 推荐岗位
  ↓
筛选城市 / 薪资 / 决策等级
  ↓
点击岗位
  ↓
进入岗位决策卡
```

关键 UX：

- 岗位卡片默认按“投递优先级”排序；
- 不要让用户自己理解复杂分数；
- 用标签直接给结论：强烈推荐 / 推荐 / 观望 / 不建议。

### 5.5 招聘官视角

```text
岗位决策卡
  ↓
打开招聘官视角
  ↓
查看第一眼印象
  ↓
查看简历疑点和筛选风险
  ↓
跳转补充素材 / 修改简历 / 准备面试
```

关键 UX：

- 招聘官视角必须短、准、有行动按钮；
- 疑点要能跳转到职业素材库；
- 可能追问要能跳转到面试作战卡。

### 5.6 管理求职过程

```text
岗位决策卡
  ↓
点击加入求职管线
  ↓
卡片进入“感兴趣”
  ↓
生成定制简历
  ↓
拖到“已定制简历”
  ↓
标记“已投递”
  ↓
设置跟进提醒
```

关键 UX：

- Kanban 拖拽是核心爽点；
- 移动端不强制拖拽，改成状态切换按钮；
- 每张卡片必须有下一步行动。

### 5.7 求职行动

```text
岗位决策卡
  ↓
生成定制简历
  ↓
查看修改前后对比
  ↓
查看证据来源
  ↓
保存为新简历版本
  ↓
生成面试作战卡
```

关键 UX：

- 简历优化结果必须分成“可直接使用”和“建议补充”；
- 证据引用要明显；
- 用户可以复制、保存、撤回。

### 5.8 简历版本实验

```text
投递反馈产生数据
  ↓
进入简历版本实验
  ↓
查看不同版本面试率
  ↓
系统建议继续使用 / 调整 / 停用某版本
```

关键 UX：

- 用“面试率”而不是复杂统计指标；
- 显示最佳版本；
- 能从版本跳转到对应简历内容；
- 结果不足时提示“数据还不够”。

### 5.9 反馈闭环

```text
求职管线
  ↓
标记岗位结果
  ↓
填写反馈原因
  ↓
反馈复盘页生成趋势
  ↓
下一轮推荐策略调整
```

关键 UX：

- 反馈表单要轻量；
- 不要求用户写长文本；
- 使用选择项 + 可选备注。

## 六、页面 UX 设计

## 6.1 登录 / 注册页

### 页面目标

让用户快速进入系统。

### 页面模块

- Logo；
- 产品一句话；
- 邮箱输入；
- 密码输入；
- 登录按钮；
- 注册入口；
- 演示账号一键进入；
- 忘记密码占位，可不实现。

### 交互状态

| 状态 | 表现 |
|---|---|
| 默认 | 展示登录表单 |
| 输入错误 | 输入框红色边框 + 错误文案 |
| 登录中 | 按钮 Loading |
| 登录成功 | 跳转首页 |
| 登录失败 | Toast 提示 |

### 移动端

- 表单居中；
- 按钮全宽；
- 演示账号入口明显；
- 不使用复杂背景动画，避免性能问题。

## 6.2 首页驾驶舱

### 页面目标

让用户 30 秒内理解当前求职状态和下一步。

### 视觉基准

首页以已确认高保真图为最终视觉 Base，前端开发优先还原以下结构：

```text
左侧固定导航
  ├── Logo
  ├── 首页 / 机会广场 / 岗位雷达 / 求职管线 / 简历工作室 / 面试作战卡 / 反馈复盘 / 设置
  └── 底部 AI 助力推广卡

顶部全局栏
  ├── 用户头像 + Demo User
  ├── 当前求职身份：AI 应用工程师
  └── 发现新版本 + 立即更新

主内容
  ├── Hero：从海投到精投，你的 AI 求职作战中枢 + 能力雷达图
  ├── 指标卡：今日优先岗位 / 强推荐岗位 / 待跟进事项 / 面试准备任务
  ├── 今日求职 Sprint
  ├── 机会热度广场
  ├── 岗位雷达 Top 推荐
  └── 求职管线
```

首页不再额外强塞所有模块，`职业素材库`、`招聘官视角`、`简历版本实验` 通过任务、岗位卡和详情页入口进入，避免首页拥挤。

### 页面模块

1. 左侧固定导航；
2. 顶部用户区；
3. 当前求职身份切换器；
4. 在线更新提示；
5. 首页 Hero 与能力雷达图；
6. 求职概览指标；
7. 今日求职 Sprint；
8. 机会热度广场；
9. 岗位雷达 Top 推荐；
10. 求职管线概览；
11. 底部 AI 助力推广卡。

### 推荐布局，桌面

```text
┌──────────┬──────────────────────────────────────────────┐
│ 左侧导航 │ 顶部栏：用户 / 身份 / 更新提示                │
│          ├──────────────────────────────┬───────────────┤
│          │ Hero 文案 + 主按钮            │ 能力雷达图     │
│          ├──────────┬──────────┬────────┬───────────────┤
│          │ 今日优先 │ 强推荐   │ 待跟进 │ 面试任务       │
│          ├─────────────────────┬────────────────────────┤
│          │ 今日求职 Sprint     │ 机会热度广场           │
│          ├─────────────────────┬────────────────────────┤
│          │ 岗位雷达 Top 推荐   │ 求职管线               │
└──────────┴─────────────────────┴────────────────────────┘
```

### 首页关键内容规范

Hero 文案：

```text
从海投到精投，你的 AI 求职作战中枢
帮你判断哪些岗位值得投、如何定制简历、如何准备面试，并持续复盘求职策略
```

Hero 主按钮：

- `查看岗位雷达`：跳转岗位雷达；
- `进入求职管线`：跳转求职管线。

指标卡：

| 指标 | 示例 | 说明 |
|---|---|---|
| 今日优先岗位 | 5 个 | 今日建议优先处理的岗位 |
| 强推荐岗位 | 12 个 | 决策卡为强推荐的岗位数量 |
| 待跟进事项 | 3 个 | 需要跟进、补充或复盘的事项 |
| 面试准备任务 | 2 个 | 当前需要准备的面试任务 |

文案注意：

- `待跟进事项` 如果数量下降，写成“较昨日减少 25%”，避免红色 `-25%` 被误解；
- 首页管线数量需要像个人求职数据，不要过大，建议 Demo 使用 `12 / 6 / 8 / 3 / 2 / 1` 这类更真实的数字；
- 登录后且已有 Demo 素材时，机会热度广场默认展示 `我的倾向`；首次进入或无画像时默认展示 `全局热度`。

### 移动端

- 改为纵向卡片流；
- 今日行动卡固定在顶部；
- 指标卡横向滑动；
- 岗位预览只展示 Top 3。

### 今日求职 Sprint

首页必须明确告诉用户今天该做什么。

示例：

```text
今日 Sprint
1. 投递 2 个 P0 岗位
2. 跟进 3 天前投递的字节岗位
3. 补充 RAG 项目素材
4. 复习系统设计：缓存一致性
```

交互：

- 标记完成；
- 跳转对应岗位 / 素材 / 面试题；

## 七、全平台适配策略

## 7.1 断点设计

| 平台 | 宽度 | 布局策略 |
|---|---:|---|
| 手机 | `< 640px` | 单列、底部导航、抽屉详情 |
| 大手机 / 小平板 | `640-767px` | 单列 + 横向卡片 |
| 平板 | `768-1023px` | 双列、顶部导航 |
| 桌面 | `1024-1439px` | 左侧导航 + 主内容 |
| 大屏 / 演示屏 | `>= 1440px` | 高信息密度、多栏、大字号重点展示 |

### 7.2 导航适配

| 平台 | 导航方式 |
|---|---|
| 手机 | 底部 Tab + 顶部标题 |
| 平板 | 顶部导航或窄侧边栏 |
| 桌面 | 左侧固定导航 |
| 大屏演示 | 左侧导航可收起，突出主舞台 |

```text
首页
机会广场
岗位雷达
```

## 八、交互状态规范

### 8.1 Loading

所有 Loading 必须带明确文案。

示例：

```text
正在加载职业素材库...
正在加载机会热度广场...
正在生成岗位决策卡...
正在生成招聘官视角...
正在更新简历版本实验...
正在同步求职管线...
```

### 8.2 Empty

空状态不能只写“暂无数据”，必须给下一步。

示例：

```text
你还没有职业素材。
先添加一个项目经历，系统才能为你生成更可信的简历建议。
[添加项目经历] [加载演示素材]
```

### 8.3 Error

错误状态必须可恢复。

示例：

```text
岗位数据加载失败。
[重试] [使用演示数据]
```

### 8.4 Success

关键动作需要即时反馈。

示例：

```text
已加入求职管线。
[查看管线] [继续看岗位]
```

### 8.5 Updating

更新状态需要全屏遮罩。

```text
正在更新 JobHunter...
✓ 已保存当前页面
✓ 正在同步最新代码
○ 正在重启服务
○ 正在恢复求职驾驶舱
```

```text
青绿色主高亮
电光蓝辅助高亮
少量紫色用于次级强调
橙色用于风险 / 警告
圆角卡片 + 细描边 + 柔和外发光
高信息密度但清晰分区
```

视觉目标：

- 像“AI 求职作战中枢”，不是普通招聘网站；
- 像“数据驾驶舱”，不是聊天机器人；
- 适合大屏演示，同时前端可实现；
- 模块复用优先，避免每页单独设计一套样式。

### 9.1 风格关键词

- 暗色科技；
- 求职雷达；
- 作战中枢；
- 数据可视化；
- 卡片化；
- 高对比；
- 克制动效。

### 9.2 色彩建议

| 用途 | 颜色 |
|---|---|
| 页面背景 | `#020817` / `#07111F` |
| 卡片背景 | `rgba(15, 30, 52, 0.72)` |
| 卡片边框 | `rgba(110, 231, 255, 0.18)` |
| 主色 | `#22E6D5` |
| 辅助蓝 | `#38BDF8` / `#3B82F6` |
| 次级紫 | `#8B5CF6` |
| 强推荐 | `#34D399` |
| 风险 | `#F97316` |
| 警告 | `#FACC15` |
| 错误 | `#EF4444` |
| 文本主色 | `#F8FAFC` |
| 文本次色 | `#94A3B8` |
| 弱文本 | `#64748B` |

颜色使用规则：

- 青绿色用于当前选中、主按钮、P0、高价值机会；
- 蓝色用于普通行动、匹配度、信息型状态；
- 紫色用于次级能力、简历、面试相关模块；
- 橙色只用于风险、警告、竞争压力；
- 红色只用于失败或确实负向的指标；
- Mock / Demo 数据使用灰色或紫灰色，避免被误解为真实来源。

### 9.4 动效建议

- 页面进入：轻微淡入；
- 卡片 Hover：轻微上浮；
- Kanban 拖拽：卡片阴影增强；
- 决策分数：环形进度动画；
- 更新状态：步骤式进度动画；
- 大屏演示：可适当增强动效。

### 9.5 首页 Base 组件样式

| 组件 | 样式要求 |
|---|---|
| 左侧导航 | 深色半透明侧栏，当前项使用青绿色描边和渐变底 |
| 顶部身份切换器 | 胶囊按钮，显示图标 + 当前身份 + 下拉箭头 |
| 更新提示 | 右上角胶囊提示，包含状态点、版本文案、立即更新按钮 |
| Hero 卡片 | 大面积玻璃卡片，左文案右雷达图，背景可带弱网格 |
| 指标卡 | 图标圆环 + 大数字 + 趋势文案 |
| Sprint 任务 | 列表行结构，左侧圆点，右侧完成按钮，P0/P1 标签 |
| 热度卡 | 方向名 + 热度大数字 + 增长折线 + 技能标签 |
| 岗位卡 | 公司标识 + 岗位名 + 来源 Badge + P 标签 + 匹配度环 |
| 管线卡 | 小型 Kanban 列，当前列使用青绿色发光强调 |
| 底部推广卡 | 低优先级，不能抢主流程视觉焦点 |

### 9.6 禁止偏离项

后续页面和前端实现避免以下方向：

- 不做成传统招聘网站白底列表；
- 不做成聊天机器人主界面；
- 不使用 Hermes / Telegram 相关视觉；
- 不使用低质 3D 插画或卡通人物；
- 不让每个页面出现完全不同的导航结构；
- 不把 `岗位决策卡` 放入左侧一级导航；
- 不在首页堆满所有二级模块，首页只承载决策概览和行动入口。

## 十三、比赛演示 UX 动线

推荐 5 分钟 Demo：

```text
登录演示账号
  ↓
首页：以求职作战中枢总览当前状态
  ↓
顶部确认当前身份：AI 应用工程师
  ↓
首页：今日 Sprint、机会热度、岗位 Top 推荐、求职管线同时出现
  ↓
机会热度广场：展示全局热度 / 我的倾向
  ↓
岗位雷达：展示 Top 5 强推荐岗位
  ↓
岗位决策卡：解释为什么值得投
  ↓
招聘官视角：指出简历亮点、疑点和可能追问
  ↓
职业素材库：从风险修复入口补充项目证据
  ↓
加入求职管线：进入已投递状态
  ↓
简历工作室：展示证据引用式优化
  ↓
简历版本实验：展示 AI 应用强化版面试率更高
  ↓
面试作战卡：展示问题和 7 天计划
  ↓
反馈复盘：标记收到面试，形成闭环
```

收尾话术：

> JobHunter 不是又一个 AI 简历生成器，而是一个可解释、可追踪、可复盘的 AI 求职作战中枢。

## 十四、结论

JobHunter 的 UX 核心不是“多做几个页面”，而是构造一个完整求职闭环：

```text
职业素材 → 岗位决策 → 求职管线 → 行动生成 → 投递反馈
```

当前阶段前端优先级最高：

- 先用 Mock 数据做出完整体验；
- 先保证桌面、移动端、大屏演示都能用；
- 先把决策卡、管线、素材库这三个差异化能力做稳定；
- 算法结果后续按 Schema 替换即可。
